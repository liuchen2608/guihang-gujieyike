# 归航 · 邀请码准入

日期：2026-08-28。状态：本地实现和接口回归完成；首批20个正式邀请码已生成，但尚未配置到线上、未发布。公开发布需用户确认。

## 玩家规则

- 首页与 GitHub 登录页仍公开；开场、游戏、结果页与反馈页需要有效邀请资格。
- 邀请码为96位随机值，显示为 `GH-` 加六组十六进制字符。忽略大小写、空格和连字符。每个初始码只可兑换一个身份。
- 初始码90天内有效；兑换后资格最长30天，且不超过邀请码有效期。过期或从配置移除的码，其关联资格不再有效。
- 匿名资格通过 HttpOnly / Secure（HTTPS）/ SameSite=Lax Cookie 保留在原浏览器。清理Cookie、换浏览器或微信与外部浏览器之间切换，不自动共享匿名资格或存档。
- 先在原浏览器兑换，再经 GitHub OAuth 绑定；绑定后，登录同一账号可恢复有效期内的资格。仅登录 GitHub 不会凭空获得邀请资格。退出登录后不能继续使用已绑定账号的资格。
- 旧存档没有删除。原匿名编号仅在第一次兑换时兼容沿用，之后读写身份以服务端通行凭证为准，不信任请求中的 playerId。已注册账户的编号不能作为匿名身份认领，已建立通行凭证的匿名编号不能被另一Cookie再次认领。
- 历史限制：旧系统没有独立匿名会话凭证，因此首次沿用旧匿名编号仍以持有该旧编号为依据，不能追溯证明其原始所有权。已泄露旧编号、清理过Cookie或首次兑换前已切换账号的情况，需要单独恢复；不要承诺完全安全的无条件自动迁移。绑定或迁移不会删除原数据。
- 匿名凭证丢失不能用同一个一次性码无限重新认领。建议在30天资格内绑定GitHub；已绑定账户可在资格过期后兑换新码。管理员恢复匿名存档应另外验证归属，不新增公开“凭编号恢复”后门。

## 实现

`InviteProvider` 提供与现有绿色界面一致的弹框，并阻止未验证时挂载受保护页面。沿用 Dialog 的关闭、焦点圈定、背景 inert、滚动恢复及手机可视高度。直接打开深层链接也进入验证页。网络断开或Cookie被阻止时保留输入，并显示明确提示。

真正的准入在服务端：

| 接口 | 权限与用途 |
| --- | --- |
| GET /api/access | 检查资格，签发无权限的预验证Cookie；不返回凭证或邀请码列表 |
| POST /api/access/redeem | 同源JSON、4KB以内；校验邀请码、频率与兑换名额 |
| GET /api/saves | 邀请凭证决定身份后读取最新存档 |
| POST /api/saves | 邀请凭证决定身份后创建存档 |
| GET /api/saves/:saveId | 邀请凭证和存档归属必须都匹配 |
| POST /api/saves/:saveId/turns | 邀请校验先于请求解析、AI调用和剧情结算 |
| POST /api/feedback | 邀请校验；存在saveId时还须核验存档归属 |

无邀请返回403和 `INVITE_REQUIRED`；兑换失败400/409，触发频率限制429（Retry-After: 600），配置缺失或服务不可用503。配置缺失/损坏时拒绝放行，不存在万能码或前端绕过开关。资格和存档GET响应不缓存。

新增 `invite_grants`、`invite_attempts` 两张D1表及迁移 `0003_fuzzy_mandrill.sql`，不改剧情存档结构。凭证和邀请码只存SHA-256摘要。条件INSERT在SQLite写锁内同时检查名额和身份，重复或并发请求不会超过maxUses。预验证Cookie先于兑换存在，兑换回复丢失后读资格可恢复，不自动重发兑换。

兑换限制为每个预验证Cookie每10分钟5次、每个IP每10分钟30次，由D1持久化计数；只保存带配置盐的IP摘要，不信任X-Forwarded-For。依赖托管边缘正确提供CF-Connecting-IP；缺失时共用保守桶。该限制不是完整的DDoS防护，也没有实现全站AI消费预算或回合限流。

GitHub绑定只接受OAuth开始时记录的已验证游客凭证，并在同一批次内转移该游客存档、反馈与资格。客户端传入的anonymousId不再决定账户合并目标。升级不能反向修复此前已经发生的身份泄露。

## 邀请码生成与管理

运行 `node scripts/create-invites.mjs 20 90` 生成20个90天有效的单次码。文件位于Git忽略的 `outputs/invitations/batch-*/`，目录/文件使用700/600权限；终端只显示路径，不显示完整码。

- `邀请码.md`：只向每位玩家单独发一个码，不公开整个文件。
- `codes.json`：本地私密记录；不要进入Git、public或聊天截图。
- `manifest.json`：服务端摘要配置，填写到Sites运行时秘密 `INVITE_CODES_JSON`；不得放到NEXT_PUBLIC或前端变量。
- 本轮正式批次：`outputs/invitations/batch-snZGb2/`，20个码，有效期至2026-11-26。仅本地文件存在，发布后才可兑换。
- 本轮本地测试批次：`outputs/invitations/batch-tnF3a4/`。不要将测试批次配置到生产；本地.env.local中配置的也是测试摘要。
- 后续新增码必须合并已有manifest，不能用新批次直接覆盖，否则会撤销旧码和关联资格。保持私密备份。
- 撤销某码：从运行时配置移除对应摘要，保留其他条目，再按Sites流程发布配置更新。此实现没有公开管理员接口，也不承诺配置更新前立即撤销。

## 发布边界

先配置正式摘要，再发布已验证源码和迁移。网站仍保持公开托管，应用内部限制试玩；不修改Sites平台访问白名单。所有未兑换的老玩家也要首次验证，原数据保留。

若回退到邀请码前的旧版本，会重新开放游戏接口；安全事故时不应盲目回退到无准入版本，应先停止入口或发布保留邀请码校验的修复。代码回退不等于数据库恢复。
